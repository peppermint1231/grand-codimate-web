# 0.13.8 · 단가표 저장 메모리·재시도 복구

단가표 명령이 전체 환자 자료, 모든 단가표 원본과 전체 수정이력 스냅샷을 로드하던 경로를 분리했다. 암호화된 SQL 행은 한 행씩 읽고, 최신 게시본·작업본과 명령 대상의 본문만 유지한다. 이력은 중복 기록 판정에 필요한 정보만 유지하며 ‘되돌리기’에서 선택한 스냅샷만 본문을 로드한다. 저장된 버전·이력은 삭제하지 않는다. 작업 화면 초기 조회도 과거 단가표 본문을 먼저 모두 유지하지 않고 현재·상담 참조 버전만 조회한다.

OneDrive 전송 대기열은 작업 ID만 먼저 읽고 개별 작업을 처리한다. 변경 자료 암호화도 병렬 전체 실행 대신 순차 처리해 일시적인 메모리 사용을 줄인다. 작업 영수증·동기화 완료 표시·암호화 엔티티 반영의 기존 트랜잭션과 백업 복구 형식을 유지한다.

저장 완료 후 응답만 잃은 경우 같은 단가표 명령을 그대로 재전송하도록 클라이언트 메모리에 작업 ID를 보존한다. 기기 보관을 사용하지 않아도 현재 화면에서 재시도할 수 있으며, 기기에 평문으로 자료를 쓰지는 않는다. 이미 완료된 작업 ID는 기존 영수증으로 응답한다. 구버전 앱이 새 ID로 다시 보내더라도 최신 게시본의 편집 내용이 완전히 같으면 새 버전·이력을 만들지 않고 기존 게시본을 확인해 준다. 실제 다른 내용이나 최신 미게시 초안이 있으면 409 충돌을 유지한다. 불확실한 결과에서는 편집 화면을 닫지 말고 같은 내용으로 다시 저장하도록 안내한다.

검증: 과거 단가표 60개·수정이력 60개에 각 250 KB 원본을 넣은 SQL 통합 시험에서 현재 단가표 3개와 이력 요약만 유지했고 명령 입력 상태가 100 KB 미만이었다. 단일 저장, 동일 ID 재전송, 새 ID 동일 내용 재확인, 실제 변경 충돌, 선택 이력 로드를 검증했다. PC 1440px·태블릿 768px·모바일 390px에서 기기 보관 없이 서버 반영 직후 503 응답을 재현하고, 편집 보존·동일 명령 재전송·게시 한 번을 확인했다. 이는 시험 자료 검증이며 실제 병원 단가표를 시험 목적으로 수정하지 않는다.
