# 0.18.37 — 개인용 OneDrive 삭제 정리 재개

개인용 OneDrive의 `permanentDelete` 호출이 400 `invalidRequest / API not found`로 거부될 때 같은 요청만 반복하던 문제를 수정합니다. 정확한 오류와 개인용 드라이브를 확인한 경우에만 별도 처리로 전환합니다. 권한·통신 오류나 업무용 드라이브 오류를 삭제 성공으로 간주하지 않습니다.

기존 원본을 이전 버전째 작업 전용 폴더로 이동하고, 다른 환자가 포함된 기록은 삭제 대상만 제거해 원래 경로에 새 파일로 만듭니다. 작업·폴더·파일 이동 의도를 저장해 재시작과 응답 유실 후에도 이어갑니다. 전용 폴더의 모든 페이지를 검사해 대상 외 파일·하위 폴더가 있으면 중단하고, 검사 당시 eTag 조건으로 해당 폴더만 휴지통으로 옮깁니다.

`awaiting-recycle-bin`은 완료가 아닙니다. 관리자가 연결 계정의 OneDrive 휴지통에서 안내된 정확한 폴더만 영구삭제한 뒤 앱에서 확인해야 합니다. 개인용 휴지통 내용은 Graph로 검증할 수 없으므로 확인자·시각을 저장하고 관리자 확인으로 명시합니다. 현재 작업 ID·폴더 이름·같은 드라이브·활성 드라이브에 폴더가 없는지 검사하고, 직원·임원의 확인 요청은 거부합니다. 대기 중 백업·복구·저장소 변경·추가 영구삭제 제한은 유지됩니다. 일반 백그라운드 업무는 계속 처리합니다.

Microsoft의 [개인용 API 미지원 답변](https://learn.microsoft.com/en-gb/answers/questions/1501170/onedrive-permanently-delete-a-file), [파일 이동 명세](https://learn.microsoft.com/en-us/graph/api/driveitem-move), [휴지통 이동 명세](https://learn.microsoft.com/en-us/graph/api/driveitem-delete)를 근거로 처리합니다. 휴지통 이동만으로 영구삭제 성공을 표시하지 않습니다.

검증: 삭제 범위·상담·사진·메모·수납·포인트·서명·복구 회귀 테스트, 개인용 처리의 재시작·전송 실패·타 환자 보존·권한·확인 절차, TypeScript·빌드·사용법 검사와 PC/태블릿/모바일 UI를 확인합니다. 운영에서는 이미 승인된 기존 삭제 작업만 이어가며 새 환자 삭제나 운영 복구 테스트는 실행하지 않습니다. APK는 이번 웹·서버 수정에 포함하지 않습니다.

사용법은 실무자·관리자 과정을 갱신하고 수료 버전과 실습 ID는 유지합니다. 기기·다운로드·외부 설문·독립 백업 등 별도 사본은 기존 감사 문서의 범위를 따릅니다.
