# 0.18.0 — 환자 상담 신청·일정과 S펜 편집

- 환자 추천을 위쪽 ‘이벤트’와 아래쪽 ‘추천시술’로 구분합니다. 홈페이지 상품만 가격·정가·할인·부가세를 공개하며 미용·보험 상품은 ‘맞춤 상담 후 안내’로 표시합니다. 환자용 API에서도 미용·보험의 숫자 가격 및 이벤트 가격 정보를 제외합니다. 원래 상담 장바구니의 가격은 유지됩니다.
- 처음 방문/재방문, 상담 희망일·시간, 요청사항을 접수합니다. 처음 방문은 생년월일·동까지 주소가 필수입니다. 기존 앱에서 들어오는 예전 형식의 접수는 호환합니다.
- 서울 시간 기준 평일 10:00~19:00(13:00~14:00 제외), 토요일 09:00~14:00, 30분 간격, 최대 90일 이내의 희망 일정을 제공합니다. 일요일·공휴일·대체공휴일 및 직원이 추가한 휴진일을 화면과 서버에서 차단합니다. 제출 시점의 휴진 설정을 재확인합니다.
- 한국 공휴일 자료는 [holidays-kr](https://github.com/hyunbinseo/holidays-kr)의 월력요항 기반 패키지 5.2027.2를 사용합니다. 현재 자료는 2027년까지이며, 자료 없는 연도는 예약을 허용하지 않습니다. 임시공휴일·병원 휴진일은 캘린더에서 추가할 수 있습니다. 이미 받은 요청은 자동 취소하지 않고 직원이 연락 후 변경합니다.
- 상담요청 캘린더에서 미배정·취소·배정/확정을 구분하고, 상담자별 색상 및 완료 시 어두운 색상을 사용합니다. 완료·진행 상담을 누르면 해당 상담으로 이동합니다. 상담으로 전환하면 담당자·일정을 이어받고, 기존 접수 보관기간 이후에도 상담 기록으로 캘린더에 남습니다.
- 직원은 다른 담당자를 배정하고 일정을 변경·확정·취소할 수 있습니다. 동시 변경 시 버전 충돌을 감지하며 환자정보 권한을 확인합니다. 확정 버튼은 직원의 연락 완료 확인이며 자동 문자나 이메일을 전송하지 않습니다.
- 재방문은 이름·전화번호 기반 환자 후보와 연동된 초진설문지 후보를 제시합니다. 동일인 여부는 직원이 확인 후 선택합니다. 신규 등록에 필요한 필드는 설문지에서 불러오거나 직원이 보완합니다.
- 새 형식의 접수 보관기간은 희망일/변경 상담일 후 30일입니다. 접수 동의문·버전(2026-10-06)에 반영했습니다. 상담 연결 시 접수 연락처·요청사항을 비우고 상담 메모/환자 기록으로 관리합니다.
- S펜의 Pointer Events 버튼 2/32를 누르는 동안 임시 지우개로 전환하고 해제 시 원래 도구로 복귀합니다. 같은 접촉 중 버튼 전환, 기존 작성자 삭제 제한, 실행취소·다시실행을 유지합니다. 활성 펜 사용 중 들어오는 터치는 무시합니다.
- 굵기 조절에 가늘기→굵기 형태의 바, 숫자, 현재 선 굵기 미리보기를 추가합니다. 일반 편집 도구와 주석 설정에 모두 적용합니다.

- 상담요청은 암호화된 Durable Object 저장소에 영구 기록한 뒤 응답합니다. OneDrive 조회·업로드를 신규 접수 응답에서 분리하고 5초 후 서버 알람으로 백업합니다. 백업 실패 시 대기 기록을 유지해 1분 간격으로 재시도합니다. 직원 목록은 백업 전에도 접수를 바로 보여줍니다. 동일 접수 재전송은 중복 등록하지 않으며 서버 인스턴스 변경 시 기존 원격 복구를 유지합니다. 전송 중 안내도 표시합니다. 네트워크·다른 서버 작업 대기시간까지 제거하는 것은 아닙니다.

## 검증

- 전체 424개 도메인/API 테스트 통과. 신규 환자 필수값·재방문·영업시간·공휴일·휴진일·다른 상담자 지정·동시 수정·취소·상담 연결 및 접수 만료 후 캘린더 유지 검증.
- 브라우저 1440/768/390px에서 가격 비공개·이벤트/추천시술 구분·첫 방문 접수·공휴일 차단·환자 후보·상담자 배정·완료 상담 링크를 확인했습니다. Chromium 실제 펜 Pointer Events로 버튼 지우개·해제 후 복귀·접촉 중 전환·다른 작성자 보호·굵기 미리보기를 확인했습니다. 물리적 갤럭시탭/S펜 하드웨어는 이 환경에서 확인하지 못했습니다.

- OneDrive 업로드가 응답하지 않아도 접수 응답 완료, 업로드 실패 후 알람 재시도, 즉시 직원 목록 조회, 중복 요청 및 인스턴스 재시작 후 복구를 테스트했습니다. 실제 환자 개인정보를 추가하는 운영 테스트는 수행하지 않았습니다.
