# 0.18.10 — 대량 환자 조회 최적화와 정보 통합

환자 이관 후 일반 화면 조회가 이관 환자 행까지 반복 스캔하여 Cloudflare 무료 요금제의 일일 SQL 읽기 한도를 소진했다. 자료 종류와 ID의 기존 복합 기본키를 사용해 필요한 구간으로 직접 접근하도록 변경했다. 작업 화면은 일반 환자 및 상담·수납·등급에 연결된 환자만 조회하고, 대량 이관 목록은 최초 검색 시 제한된 묶음으로 복호화하여 별도 캐시한다. 새 인덱스 생성이나 환자 데이터 재작성은 필요하지 않다.

서버 한도 오류는 로그인 만료와 구분하여 503 및 다음 초기화 시각을 안내한다. 로그인 복원 실패 시 저장된 로그인 정보를 유지하고 다시 연결할 수 있게 했다. 기기 암호화 보관을 사용한 경우 12시간 이내의 저장 자료를 기기 보관 암호로 열 수 있다. 내부 사용자 ID를 입력할 필요 없이 저장된 계정을 찾아 잠금을 해제하며, 서버 전송 대기열을 유지한다.

이관 기준은 사용자가 지정한 이름·전화번호 일치로 통합한다. 관리자 전용 `patient.import.enrich`는 동일한 이름·전화번호와 현재 수정 버전을 확인한 뒤 참고정보를 보완한다. 환자 ID·환자번호·생성일·상담·수납 연결을 유지하고 원본 누적액은 중복 합산하지 않는다. 기존 VIP 계정과 포인트를 재지급하지 않는다. 주소가 불완전해도 등록하며 전체 지역 통계에 지역 누락으로 집계한다.

검증: 전체 463개 테스트 및 TypeScript·웹 빌드 통과. 65,000개 이관 레코드가 존재할 때 일반 환자·설정·빈 수납 조회가 복합 기본키 검색을 사용하는지 확인했다. SQLite 측정에서 설정 한 행을 찾는 기존 조회는 520,022 VM 단계, 개선된 조회는 26단계였다(로컬 측정이며 실제 서비스 시간이나 Cloudflare 과금 수치가 아님).

브라우저 검증: PC 1440px·태블릿 768px·모바일 390px에서 한도 오류 시 저장된 네이티브 로그인 유지, 다시 연결, 기기 보관 암호 잠금 해제, 12시간 경과한 오프라인 세션 차단을 확인했다. 브라우저 오류·서버 쓰기 요청 0건. APK 0.18.10/versionCode 80은 v2 서명 및 내장 웹 자산 48개 일치를 확인했다.

운영 이관 진행: 최초 64,980명에 이어 2,500명 추가 저장 후 서버 일일 한도로 중단했다. 남은 신규 324명과 기존 환자 40명의 통합 정보는 비공개 폴더에 준비했으며 동일 작업 ID로 안전하게 재개한다. 원본 67,852행은 이름·전화번호 기준 67,817명, 중복 추가 행 35개로 정리된다. 주민번호 날짜가 유효하지 않거나 미래인 원본 1,013행을 다시 확인했으며, 동일인의 다른 행에서 날짜가 확인되는 한 명을 제외한 1,012명의 날짜는 미확정으로 유지한다. 원본 주민번호는 서버에 저장하지 않는다.

이미 소진된 무료 한도는 이 코드로 초기화할 수 없다. Cloudflare 무료 한도 초기화(UTC 자정, 한국시간 오전 9시) 또는 계정의 Workers Paid 전환이 필요하다.

운영 마무리: Workers Paid 전환 및 0.18.10 배포 후 기존 저장 대기 1건을 정상 동기화하고 남은 신규 324명을 등록했다. 추가 신규 총 2,824명 및 기존 환자 40명의 정보 통합을 완료했다. 활성 환자는 67,824명이며 기존 수납 내역·환자 식별자·VIP 혜택은 유지되고 저장 대기는 0건이다. 운영 브라우저 PC 1440px·태블릿 768px·모바일 390px에서 로그인·이관 환자 검색·상세 참고정보 조회를 확인했으며 브라우저 오류는 없었다. 비공개 확인용 엑셀도 완료 상태로 갱신했다.
